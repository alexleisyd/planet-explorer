# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Planet Explorer is a browser game: fly a survey craft around 24 solar-system bodies rendered with fully procedural (asset-free) surfaces. Three files, no build step, no network:

- `index.html` — the entire game (markup, CSS, and ~2,100 lines of JS in one inline `<script>`)
- `three.min.js` — vendored Three.js **r128** (the only dependency; APIs must stay r128-compatible, e.g. `outputEncoding`/`sRGBEncoding`, `mapTexelToLinear` in shader patches)
- `README.md`

## Running / verifying

Open `index.html` directly in a browser (`open index.html`) — `file://` works, no server needed. There are no tests, no linter, no package manager, and no build. Verify changes by loading the page and watching the console; a texture-baking bug usually shows as a stuck "Scanning surface — N%" overlay.

Three localStorage keys hold persistent state; clear them to test first-run behavior:
- `pe-pilot` — `{mass, age}` for the "You, here" panel
- `pe-surveyed` — array of surveyed body ids (mission badges)
- `pe-datapanel` — `"1"`/`"0"`, whether the body-data panel is unfolded (defaults to folded below 900px)

**Saved state and its native mirror (`index.html:2341`)** — localStorage stays the source of truth, because all three keys are read *synchronously* as the game starts. On native each write is also mirrored into the app's own preferences (`store()`), and anything the WebView has lost comes back at startup (`restoreState()`). Things to keep in mind when touching it:
- Capacitor Preferences is **async**, i.e. it resolves after the value has already been read, so a restored key has to be *re-applied*, not merely written back. Each reader registers how, beside its own read, in `reload`.
- `lost` is snapshotted **before** the game's own startup writes: `setData` writes `pe-datapanel` on the first frame, so a check made later can never tell that the key had been evicted.
- This exists for iOS, where WebKit may evict website data under storage pressure. On Android it is redundant but harmless, and Capacitor plugins are per-project rather than per-platform anyway.
- To test the restore path, wipe the WebView's storage without touching the app's: on a simulator, `rm -rf <data container>/Library/WebKit/<bundle id>/WebsiteData/{Default,LocalStorage}` with the app terminated, then relaunch and check the mission count.

**iPad is the primary surface**, so check any layout change at 1180×730 and 1024×690 (landscape) and 820×1080 and 744×960 (portrait), not just a desktop window. A browser cannot be asked to report `pointer:coarse`, so to exercise the touch branch make a copy with the media query and the `coarse` flag forced on:

```
python3 - <<'EOF'
s=open('index.html').read()
s=s.replace('@media (pointer:coarse){','@media (min-width:1px){',1)
s=s.replace('const coarse=matchMedia("(pointer:coarse)").matches;','const coarse=true;',1)
open('/tmp/pe-touch.html','w').write(s)
EOF
```

Two traps in any harness that measures the HUD, both of which quietly invalidate a whole run:
- **`--disable-gpu` kills WebGL**, so the game's script throws at `new THREE.WebGLRenderer` and never reaches the HUD wiring. The panels still lay out from CSS, so a probe reports plausible-looking boxes for a page where nothing ran — including the data panel *unfolded*, because `setData` never ran to add `data-collapsed`. Use `--enable-unsafe-swiftshader` in headless Chrome and confirm the script finished (`document.querySelectorAll(".flare").length` — the flares are built on the last lines; the selector dots are static markup and prove nothing).
- **Chrome's `mobile:true` device emulation turns on text autosizing**, which inflates the HUD's fonts and invents collisions no device has. Force the touch branch with the copy above instead.

A headless window is 1280px wide, so the *first* load of the page stores `pe-datapanel:"1"` and every later one reads it back — fold the panel explicitly before measuring below 900px.

## Architecture

Everything is driven by data tables keyed on body `id`. To add or change a world you edit table entries, not code paths.

**Body catalogue (`index.html:481`)** — `BODIES` is the single source of truth: id, display name/class, real `radiusKm` / `dayH` / `distM`, HUD `fact`, selector-strip `dot`, plus optional `atmo`, `rings`, `clouds`, `parent` (moons), `scaleAxes` (Haumea's egg), `railY`/`railDX` (strip layout nudges). Parallel keyed tables: `TILTS` (:559, the lean each body is *rendered* with), `TILT_DEG` (:563, the real obliquity the science layers quote — the two must stay in agreement, and a body with no measured pole is left out of `TILT_DEG` rather than given a number), `GRAV` (:565), `ORBIT_YEARS` (:2501).

**Earth's real map (`index.html:858`–`:1147`)** — Earth is the exception to "procedural everything": `COASTS`, `INLAND_SEAS`, `ICE_SHEETS` and `RANGES` are hand-traced `[lon°,lat°]` geography. `GEO` (:1058) rasterises them once into four byte fields — `land`, `cont` (a wide blur of `land`, i.e. how deep inside a continent, which drives both the offshore shelf and interior aridity), `range`, `ice` — sampled bilinearly. Both `SURFACES.earth` and `HFIELDS.earth` go through `earthGeo` (:1138), which applies the same two-scale domain warp to the lookup so shading and relief share one coastline and no polygon edge shows. Shapes are drawn at three longitude offsets so seam-crossing outlines wrap; `lat` runs *negative-north* (true latitude is `-lat`).

**Procedural surfaces (`index.html:784`–`:1470`)** — a seeded 3D value-noise `fbm` feeds per-body functions in `SURFACES`, each mapping a unit-sphere point `(px,py,pz,lat,lon)` to an RGB(A) triple. `bakeSurface` walks an equirectangular canvas in **~14 ms slices** with `await setTimeout(0)` between them so the page never freezes, reporting progress to the scan overlay. It takes an optional `live` predicate checked *after* each yield and throws `ABORT` when it goes false, which is how a superseded selection stops a bake it no longer needs — see the body cache below. Companion tables, all keyed by body id:
- `POSTS` (:1424) — 2D canvas passes after the noise pass (crater stamping, Ceres' bright faculae)
- `DISPLACE` (:1452) — displacement scale in body radii; presence of an entry is what makes a world get real relief (and a 320×240 sphere instead of 128×96)
- `HFIELDS` (:1465) / `HF_DEFAULT` (:1464) — the height field baked into the displacement map
- `HCRATERS` (:1458) — crater counts stamped into the *height* map; these must stay in sync with the counts in `POSTS`, and `craterList` (:784) is deterministic and resolution-independent so color and relief line up
- `TEX_SIZES` (:1901) — per-id override; everything else bakes at 2048×1024. Every size goes through `texSize` (:1915), which halves each edge on a phone and clamps to `maxTextureSize` — see the body cache below

**Named landmarks (`index.html:610`–`:751`)** — `LANDMARKS` is a per-id list of real places at real coordinates (latitude °N, **east** longitude °), and it is the single source for all three of: the color stamp, the relief stamp, and the callout. `surfaceTexture` applies it centrally — `lmPaint` wraps the `SURFACES` function and `lmRelief` wraps the height field — so adding a landmark never means editing a surface function. Points to keep in mind:
- **The bake runs 180° out of phase with map longitude.** `GEO` rasterises Earth with `x=(lon+180)/360`, which fixed the convention for every body; `lmT` and `lmDir` are the only two places that +180 appears, and they must agree.
- The bake's `(px,py,pz)` triple is mirrored in x relative to the mesh (`SphereGeometry` maps texture u to `-cos φ`), so `lmDir` is *not* the bake point. Both frames still measure east as increasing longitude, which is why an elongated feature keeps its bearing.
- `lmT` returns distance from a feature's centre as a fraction of its own radius (1 = rim), measured in degrees of arc east/north — so a feature's size comes straight from its real width, `(D/2)/R` radians. `lmShape` turns that into the height profile per kind (crater bowl + rim, volcano cone + caldera, canyon, basin), and `lvl` flattens a plain to its own level instead.
- Any body carrying a relief landmark bakes its height map at **2× the usual size** — 2048 rather than 1024, and 1024 rather than 512 once `texSize` has halved it for a phone. The two `softenCanvas` passes are what forces this: measured against the unsoftened bake, the deepest point of Valles Marineris (`ry` 1.7°, so 3.4° across) keeps 99% of its depth at 2048, 93% at 1024, and only 77% at 512. 512 is therefore reserved for the bodies whose height field is nothing but `fbm`.
- Entries with no `c`/`h`/`lvl` are label-only, for features the surface already draws (Earth's traced geography, the Red and Dark Spots, Triton's cap). Worlds whose visible surface is cloud rather than ground — Venus, Uranus — deliberately have no entry at all.

**Materials (`planetMaterial`, `index.html:1683`)** — `MeshStandardMaterial` patched via `onBeforeCompile`: a mirrored-repeat detail texture faded in by view distance, plus the optional wind shader that slides `vUv.x` over time. Jupiter counterflows band pairs; Neptune slides the whole deck retrograde. The band profile is deliberately clamped to ±1 (rigid bands, shear confined to thin lanes) — a smooth latitude profile shears the texture without bound and destroys the clouds within minutes. `customProgramCacheKey` is required because all planet materials share one `onBeforeCompile` source.

**Body construction (`buildBody`/`makeBody`, `index.html:1878`)** — assembles one `THREE.Group` per body and caches it in `built` (textures cached separately in `texCache`). Structure: `group` (holds tilt, atmosphere, rings, moon pivots, parent backdrop) → `spinGroup` (surface mesh, clouds, spot overlay, solar prominences). `COMPANIONS` (:1865) defines orbiting moons with compressed distances and ~2.5× exaggerated sizes; negative `T` = retrograde. When a **moon** is the target, the same table is inverted to hang the host planet in its sky as a backdrop that orbits the moon at the moon's period.

**Body cache and texture lifetime (`index.html:1878`–`:2020`)** — a body does *not* bake once per session: a 2048×1024 map is resident twice over (the source canvas three keeps on `texture.image`, plus the GPU copy) at ~19.6 MB, so keeping all 24 would allocate ~800 MB and never return it. `built` is therefore an LRU of `BODY_CACHE` bodies, and maps are **reference-counted** across it in `texRef` rather than owned by one body — a texture is shared, since Jupiter's build bakes its four moons and a moon's build bakes its host for the backdrop in its sky, so it is only freed when the last holder is evicted. Things that will bite:
- `TIER` (:1893) is the one device probe — 0 phone, 1 tablet, 2 desktop — and both how many bodies stay resident (`BODY_CACHE`, 2 / 3 / 5) and how big their maps are (`texSize`) hang off it, because they are the same question. `navigator.deviceMemory` is Chromium-only, so WebKit falls through to the viewport, the same signal the rest of the HUD uses.
- **Only the phone tier shrinks maps**, halving every edge and so quartering the pixels: ~19.6 MB becomes ~4.9 MB, and the two bodies a phone keeps cost less than one did. Jupiter — the worst case, five maps plus four moons — drops from 256 MB of maps and a 9.8 s build to 48 MB and 2.5 s; a full 24-body tour ends at 12 MB resident. The obvious middle step of 1536 for tablets is deliberately absent: a non-power-of-two map with mipmaps is silently rescaled *up* to 2048 on a WebGL1 context, so it can cost more than it saves, and the iPad is the primary surface anyway.
- The `softenCanvas` factor stays at 2 through all of this. It is a texel-scale prefilter for a map that is also the `bumpMap`, so it is meant to be constant in texels, not in degrees; what protects narrow relief at low resolution is the height map's own 2× rule, not a smaller kernel.
- `releaseBody` must dispose textures by hand: `material.dispose()` deliberately leaves them alone in three. `TEX_KEYS` is what catches the maps a body owns outright (ring, corona, prominence — none of them in `texCache`). `DETAIL_TEX` is shared by every planet material and must never go, and `Sprite.geometry` is a single module-level buffer in r128, so `!o.isSprite` guards it — disposing it would take out every sprite in the scene.
- Refs are claimed **eagerly**, as each map is awaited rather than when the body finishes, because a bake runs for seconds and a selection made mid-bake must not evict a texture an in-flight build is already holding.
- `buildBody` dedupes in flight through `building`, and each waiter keeps its own liveness test in `lives` — the build outlives all of them, so the superseded tap of a pair on the *same* dot can't cancel what the other is still waiting for. `setTarget` cannot guard this itself: `current` only moves once a bake finishes.
- **A superseded selection cancels its bakes.** `setTarget` passes `()=>req===reqSeq`, and an abandoned build throws `ABORT` at its next slice boundary or between maps; `buildBody` then hands back its claims and disposes the partial group, and `surfaceTexture` refuses to cache a half-walked canvas. Without this, tapping across the strip ran every bake to completion: 12 taps took ~15 s to show the last world and held ten bodies' maps at once, against ~4 s and two now.
- The liveness a *texture* bake reads is derived from `building` — "is some live build still claiming this id" — and **must not** be `texRef[id]>0`. One bake serves every build that wants the map, but the refcount is held by the abandoned build, which cannot let go until the bake returns, so a count keeps each doomed build alive for one full texture before it notices. This was the first version and it cancelled nothing.
- The body on screen and the one just built are pinned in `trimCache`, so walking the selector strip faster than a bake completes can never evict what it is about to show.

Physical invariants baked into `buildBody` — preserve them when touching spin/orbit code: every moon is tidally locked (`spinRate` = its orbit rate, so the host stays over one face), Pluto is locked back to Charon, and Triton's retrograde `T` propagates to both its spin and its sky. Retrograde rotation is expressed the way nature does it — as an obliquity past 90° in `TILTS` (Venus 177°, Pluto 123°), not as a negative spin rate.

**Camera & HUD (`index.html:1966`–`:2500`)** — no OrbitControls; a hand-rolled spherical camera (`ctl`) with drag momentum, exponential smoothing, `MIN_D`/`MAX_D` clamps, and rotation damped near the surface. Distance is in body radii; `radiusKm` converts it to km wherever a number is quoted (the data panel and the scale overlay — the live range and velocity tapes were removed as noise, since neither told the player anything the view does not). `setTarget` (:2428) is the async selection path — it uses a `reqSeq` guard so a newer selection supersedes an in-flight bake. The bottom selector strip and the full-screen orbital plot are both DOM/2D-canvas, not WebGL.

**Flight input** — pointer listeners hang off `window`, not the canvas, so a drag that begins on top of a panel still flies the craft; `CONTROLS`/`isControl` is the one list of things that swallow a gesture instead (buttons, inputs, the selector strip, the three dialogs). A `touches` Map keyed by `pointerId` is what makes one finger rotate and two pinch — `pinchD` carries the previous finger gap and its ratio drives `tDist` on the same exponential curve as the wheel. Dropping from two fingers to one re-anchors `ctl.lx/ly` on the finger still down; without that the view snaps by the width of the gap. `touch-action:none` on the canvas and `#hud` (and `gesturestart` preventDefault) is what stops Safari swallowing the drag as a page pan or zoom.

**Responsive HUD** — every panel is placed off `--edge`/`--edgeT`/`--edgeB`/`--edgeL`/`--edgeR` (which fold in `env(safe-area-inset-*)`), plus `--strip`/`--railY` for the selector and `--hudBtnY` for the view buttons, so moving the HUD is a matter of changing a number rather than chasing offsets. Seven breakpoints, in cascade order: `max-width:1300px` pulls the edges in for iPad landscape; `pointer:coarse` grows every control to a finger target (`.tick` keeps its 34px box and reaches 46px via an inset `::after`, so a "−" does not become a slab) and raises the strip to 92px; `max-width:900px` moves the instrument column into a bottom console — day length, the time warp and the overlay buttons, the last lifted onto their own line and the data panel folded to its heading; `max-height:900px and min-width:901px` bottom-anchors the data panel, which centred would run into the mission card; then the three phone steps below.

**Phones (`index.html:359`–`:445`)** — a phone has half the width of the narrowest tablet this was built for and, in landscape, half the height, so the chrome gives way rather than shrinking: the globe is the game. `max-width:480px` stacks every panel down the left edge — nothing sits beside anything else, which is the only way 390px works — drops the rotation readout (it is "day length" in the data panel), and puts the mission clue at full width under the view buttons. `max-width:480px and max-height:700px` tightens that stack for a 568px screen, where the console and strip claim 220px before anything is placed. `max-width:360px` steps the overlay labels down once more. `max-height:450px` is the landscape case, and the reason it exists is that `max-height:900px and min-width:901px` **excluded every phone**: 844 < 901, so an iPhone on its side fell into the portrait console branch and the centred data panel ran straight through the mission card. Traps, all of them found by measuring rather than by reading:
- **`--strip`/`--railY` are deliberately not touched here.** `posFor`'s `RAIL_Y`/`MOON_TOP`/`MOON_DY` are pinned to them, and a rail that no longer agrees drops the moon columns off the strip.
- **`--console` must equal the console's real height** — readout row + gap + overlay row (136px), plus whatever that breakpoint lifts `#instruments` clear of the strip by. The readout row is 73px because the time-warp cell is the tallest thing in it (label, buttons, and the `1 s = 6 min here` sub-line), so hiding a plain readout beside it does not change the number. A small phone is **150px**, not the 124px the two rows measure, because `#instruments` sits 20px above the strip there rather than 14; at 142 the folded panel's bottom edge landed 2px inside the overlay row. The data panel hangs off this number, so any shortfall puts its heading inside the buttons, and the folded panel is **62px** at finger size, not the ~30px the heading looks like.
- **The three overlay buttons must stay on one line.** Wrapped, the row grows from 37px to ~92px and takes `--console` with it; the tracking and side padding are what buy the width back. The landscape branch needs the same rule for a different reason — it is reached by *height*, so a 667px-wide phone on its side lands there with only 367px of console once the data panel's column is reserved, and the wrapped row then ran up into the view buttons.
- **`--hudBtnY` is 76px in landscape and 70px one step narrower**, which reads backwards until you notice what `3.4vw` does to `#bodyName`: a phone on its side is 844–932px wide, so the name is pinned at its 26px *maximum*, where in portrait at 390–430px it is at the 18px minimum. The tallest target block of any breakpoint was sitting under the shortest budget.
- **The selector strip is centred on the viewport, not inset like every other panel**, so it takes the safe area as a width cap through `--stripW` rather than an offset. A notched phone held sideways loses 62px to the sensor housing on each side, and the first dot on the rail was landing under it — `86vw`/`94vw`/`88vw` are all wider than that leaves.
- `.cell.ov` is positioned *outside* `#instruments` (`bottom:calc(100% + 14px)`), so it is absent from the parent's bounding box — check it separately or a collision with it is invisible to measurement.
- A few bodies carry a `railY` nudge that sits a row below the rail; with only 12–16px of bottom inset left, that reached past the screen edge, so the strip lifts slightly on phones.
- What gives way, and why: the hint (every key it names has a button), the mission status line at 568px ("set a course below" points at a strip already on screen), and the mission card's height. Unfolding the data panel on a small phone deliberately covers the mission card — it is a tap, and the clue returns when it closes.

**View controls (`#viewbtns`)** — the hide-HUD and full-screen buttons, parked under the target block in the one patch of sky no panel wants. `#hud.hidden` (the H key) fades every direct child of `#hud` except `#scan`, `#stamp` and `#viewbtns`, so the column must stay a *sibling* of `#target` rather than a child; `#fsBtn` is then hidden separately, leaving exactly one way back from a bare globe. Keep the two buttons on **one row** — stacking them pushes `#instruments` (which hangs off `--hudBtnY` in short landscape) down past what a 690px-tall iPad has left. Full screen is feature-detected against both the standard and `webkit` forms *and* `fullscreenEnabled` (an iframe can forbid it), and is suppressed in a home-screen web app or a packaged native build, which have no chrome to shed; where any of that fails the button stays `hidden` rather than sitting there dead. iPadOS has had the API on ordinary elements since 16.4, iPhone since Safari 17.2. **Measured, against the expectation:** a packaged WKWebView reports `fullscreenEnabled` **true** (iOS 26), so nothing about the feature detection would have hidden this button on iOS — the explicit `window.Capacitor` probe is the only thing that does. The coarse hint drops its "⤢ fills the screen" clause when the button is hidden, so the copy never names a control that is not on screen. The label is driven by `fullscreenchange`, never by the click, because Esc and system gestures leave full screen without asking.

**Touch and the rail** — the moons of a planet all share its x on the selector strip and can only separate vertically, so `RAIL_Y`/`MOON_TOP`/`MOON_DY` in `posFor` shift with `coarse` (18px apart instead of 12) and **must stay in step with the `--strip`/`--railY` pair in the coarse CSS**. Sub-dots then get a wide, short hit box (`padding:6px 13px`) that tiles without overlapping the moon above. The orbital plot widens its moon orbits and doubles both hit radii on `coarse` for the same reason. Anything the hints offer a key for also has a button — `#warpHold` for space, `#scaleBtn` moved into the Overlays cell beside G and N — and the hint, `#orreryHint` and `#scaleFoot` copy is rewritten for gestures when `coarse` (an iPad has no Esc; all three dialogs close on a tap outside). The `· key g` tails on the buttons themselves are `<i class="k">` spans, and `coarse` hides all five: a touch device has no keyboard, so the label would name a control that is not on the device. The **shortcuts stay bound** — an iPad with a keyboard case still answers g/n/x/h/f — and the two phone breakpoints keep their own `.k` rules, which drop the tails for width rather than for input (a narrow desktop window is still fine-pointer and still shows them).

**Time warp (`index.html:2141`)** — `TIME_STOPS` is the warp ladder; `timeScale()` multiplies the *world* clock only. The main loop keeps two deltas: `dt` (real seconds — camera smoothing, inertia, the survey hold) and `adt = dt*timeScale()` (every spin, moon orbit, backdrop orbit and prominence). Because a rotation always takes `dayH*10` seconds, one second at 1× is six minutes of local day on *every* body, which is what the readout states. Two deliberate exceptions: companion-moon orbits still use the compressed `COMPANIONS` periods, so they run fast against that clock, and the wind uniforms advance on `wdt`, capped at 2× — `jetTime` smears the cloud texture in proportion to elapsed time, so letting it run at 60× grinds the bands to mush.

**Science layers (`index.html:2191`)** — the G overlay. `buildLayers` rebuilds one `THREE.Group` per target: a body frame carrying the same `TILTS` lean as `buildBody` (axis, poles, equator, a spin arrow whose pivot swings to face the camera each frame), plus a Sun-frame child holding the terminator ring and sub-solar marker, skipped for Sol. Callouts are DOM elements in `#layerLabels`, projected each frame by `updateLayerLabels` and hidden by a `p·camera > 1` horizon test unless flagged `through`. The cage is always a plain sphere at `LAYER_R` — an ellipse fitted to Haumea's egg would swing off the surface as it tumbles.

**Landmark callouts (`index.html:2323`)** — the N overlay, and the consumer of `LANDMARKS`. `buildMarks` hangs a tick, an outline (anything ≥1.5° across) and a DOM chip off one of three frames that copy a rotation each frame in `updateMarks`: `body` (the target's `spinGroup`), `spot` (the Red/Dark Spot overlay meshes, which drift across the winds on their own), and `tilt` (the untilted-but-leaning `group`, for ring gaps, whose pin rides round to the camera-facing side). Pins sit at `1.035 + dscale*0.5` radii — clear of the relief, which pushes out by half the displacement scale, and of Earth's cloud shell. The same `p·camera > 1` horizon test hides both the chip *and* its 3D objects: standing off the surface, they would otherwise swing clear of the limb and hang in space. Only the pin nearest the crosshair gets class `near`, which is what unfolds its note.

**Sense of scale (`index.html:2640`)** — the X overlay. `updateScale` computes everything from `radiusKm` and `distM` — nothing is a stored string: the two discs are drawn at one scale (the smaller is *meant* to come out as a dot), the model line shrinks the system until the Sun is a 30 cm beach ball (`MODEL_K`), and the rows work light, radio and a 900 km/h airliner over the same gaps. Distances to Earth are closest approach (`|distM − AU|`, or the body's own `distM` if it orbits Earth); moons take their Sun distance from their parent.

**Missions (`index.html:2692`)** — `MISSIONS` pairs a clue with a target id and a debrief. Progress is a `Set` persisted to `pe-surveyed`; `surveyTick` runs each frame and awards a badge after holding inside `SURVEY_DIST` radii for `SURVEY_TIME` seconds.

**Main loop (`index.html:2871`)** — single `requestAnimationFrame` tick: keyboard nudges, inertia, camera smoothing, per-body animation (spin, wind uniforms, moon pivots, parent backdrop orbit, solar prominence breathing), `surveyTick`, lens flares, both label overlays, render.

## The native shells (`mobile/`)

Capacitor 8 wrappers for Google Play (`mobile/android/`) and the App Store (`mobile/ios/`), kept in `mobile/` precisely so the repo root stays the three files and `open index.html` keeps working. One application id, `au.com.lionforce.planetexplorer`, one version number, and one game: **`index.html` carries three `window.Capacitor` probes and nothing else** — `#fsBtn` suppression, the Android hardware back button, and the preferences mirror. All three are inert in a browser and all three read the plugin off `window.Capacitor.Plugins` at runtime, which is what keeps the game free of imports and a build step.

- **`mobile/www/` is a build output, not a source.** `npm run copy` deletes it and re-copies `index.html` + `three.min.js` from the repo root; `npm run sync` does that and then `cap sync` for both platforms. Editing anything under `www/`, `android/app/src/main/assets/public/` or `ios/App/App/public/` is editing a file that the next sync throws away.
- **Any change to `index.html` invalidates both built artifacts.** The AAB and the archive embed a copy of the game, so a layout fix means a rebuild before upload, not just a re-sync.
- `npm run icons` re-renders every raster icon — the iOS `AppIcon` and the Play listing's 512 — from `store/icon-source.svg` through headless Chrome. The iOS one is cropped to the middle 76 of the 108-unit adaptive canvas: Android masks its icon to the middle 66, iOS rounds the corners of the whole square, so the same art has to sit at two different scales. ImageMagick then strips the alpha channel, which Apple rejects even when it is opaque everywhere.

### Android

`minSdk 29` (the tested floor and the installable floor are the same number on purpose), `compileSdk`/`targetSdk 36`.
- **The APK declares no permissions.** Capacitor scaffolds `android.permission.INTERNET` and it is deliberately deleted from `AndroidManifest.xml` — the game makes no network request and the WebView serves `https://localhost` out of the packaged assets through `WebViewAssetLoader`, which never opens a socket. Verified on the built APK, which carries only androidx's own `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. If a build ever shows a blank WebView, that line is the first thing to put back.
- `MainActivity` hides both system bars (transient-by-swipe) and re-hides them in `onWindowFocusChanged`, and sets `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` **in code rather than in the theme**, because whether `postSplashScreenTheme` has been applied by the time the window exists depends on the splash plugin being installed. The cutout mode is what makes the WebView report a real `env(safe-area-inset-*)` for `--edgeT`/`--edgeB`/`--edgeL`/`--edgeR`.
- The hardware back button closes the topmost open dialog, and at the root **minimises, never exits**: finishing the activity throws away the body cache and any bake in flight, and a back swipe should not cost the player seconds of re-scanning. Verified — same pid after back, state intact on resume.
- `androidScheme` is pinned to `https` in `capacitor.config.json`. Changing it changes the WebView's origin and silently drops every `pe-*` localStorage key with it.
- Android's one-time "Viewing full screen" confirmation panel takes focus over the game on first launch and swallows the first back press. It is a system notice, not a bug — `adb shell settings put secure immersive_mode_confirmations confirmed` silences it for testing.
- Debug builds are debuggable over the WebView's DevTools socket, which is how the on-device numbers were measured: `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`, then drive CDP `Runtime.evaluate` over the plain `WebSocket` in Node 22 — no client library needed. Release builds are not debuggable, by design, so `adb install -r` of a debug APK over an installed release one fails on the signature; uninstall first. That failure is easy to miss if you only look at the last line of the install output.
- **The launcher icon has no bitmaps either.** Three vector drawables — background, foreground, and a flat `ic_launcher_monochrome` for Android 13 themed icons — referenced from `mipmap-anydpi-v26/`. minSdk 29 means every device supports adaptive icons, so Capacitor's density-bucketed PNGs were deleted rather than kept as a dead fallback (−485 KB). All the art sits inside a radius of 33dp about the centre of the 108dp canvas, the safe zone any launcher mask keeps. Two traps: an XML comment **cannot contain a double hyphen**, so CSS variable names have to be spelled out in these files; and gradient coordinates in a `VectorDrawable` are absolute viewport units, not the fractions an SVG `radialGradient` takes. `mobile/store/icon-source.svg` is the same paths, and the 512 store icon is rendered from it.
- Release signing reads an optional `mobile/android/keystore.properties`; without it the release build comes out **unsigned rather than failing**, so a fresh clone still builds. Both that file and the `.jks` are gitignored. R8 is off deliberately — the dex is Capacitor and androidx, the game is one HTML file in assets that shrinking cannot touch, and Capacitor resolves plugins reflectively.
- `mobile/store/PLAY-LISTING.md` holds the Console answer sheet — listing copy, Data Safety, IARC, rollout — with `DECIDE` markers where the call is the owner's rather than the code's. The **privacy policy is not in this repo**: it is live at `https://www.lionforce.com.au/privacy/planet-explorer`, beside the Alphabet Match and Number Friends policies, one page per app in `lion-force-web`. `docs/privacy.html` is a superseded standalone draft.

### iOS

`IPHONEOS_DEPLOYMENT_TARGET 15.0`, universal (`TARGETED_DEVICE_FAMILY 1,2`). **CocoaPods is not involved**: Capacitor 8 declares plugins through a generated `ios/App/CapApp-SPM/Package.swift`, so a build needs nothing but Xcode.

- **Nothing to declare.** The app requests no permission of any kind, uses no entitlement, and `UIRequiredDeviceCapabilities` is corrected from Capacitor's `armv7` to `arm64` — a 32-bit claim no device that can run iOS 15 makes any more.
- The status bar is hidden in `Info.plist` (`UIStatusBarHidden` **with** `UIViewControllerBasedStatusBarAppearance` false, or the view controller wins), which is the same decision `MainActivity` makes on Android. Hiding it does **not** shrink the safe area: measured on an iPhone 17 Pro, `env(safe-area-inset-top)` still reports 62px in portrait, and 62px on each *side* in landscape.
- `ios.contentInset` is `never` so `viewport-fit=cover` reaches the edges, and **`iosScheme` is pinned to `capacitor`** for the same reason `androidScheme` is pinned to `https`: changing the WebView's origin silently drops every `pe-*` key with it. `limitsNavigationsToAppBoundDomains` is deliberately *not* set — it needs a `WKAppBoundDomains` list to go with it, and an app that makes no request has nothing to gain from it.
- The launch screen is a plain black `UIView` in the storyboard with `useSafeAreas="NO"`, and Capacitor's three 2732px `Splash` PNGs are deleted. The game opens on an unlit sky, so a black field is a frame-accurate continuation of it; anything inset from the safe area would flash white in a corner.
- **`fullscreenEnabled` is `true` in a packaged WKWebView** (iOS 26), against the expectation that WebKit's element-fullscreen default would hide `#fsBtn` by itself. The `window.Capacitor` probe is the only thing that hides it.
- **There is no CDP for a WKWebView.** The way to get numbers off a simulator without Xcode in the loop is to append a throwaway script to `www/index.html`, have it write JSON into a localStorage key the game does not use, and read it back on the host out of `<data container>/Library/WebKit/<bundle id>/WebsiteData/.../localstorage.sqlite3`. Two details: the value is a **UTF-16 blob**, so `cast(value as text)` truncates it at the first NUL and `hex(value)` + `bytes.fromhex(...).decode("utf-16-le")` is the way to read it; and localStorage is flushed to that file lazily, so terminate the app first. `UserDefaults` lags too — `plutil -p` right after a terminate can show fewer keys than the app wrote.
- **A simulator cannot be rotated from the command line, and cannot be tapped at all** without granting Accessibility to the terminal. Landscape is measured by building a copy whose `UISupportedInterfaceOrientations` is landscape-only, which makes iOS turn the interface and report the real landscape insets. Real touch delivery through the WebView is the one thing left to a physical device; `pointer:coarse` is confirmed true, and the pinch/re-anchor logic is exercised with synthetic `PointerEvent`s.
- **An iPad always resolves to `TIER` 1**, whatever its age: `navigator.deviceMemory` does not exist in WebKit and the viewport fallback cannot tell an iPad Pro M5 from a 2 GB iPad from 2017, which will bake 2048px maps and hold three bodies. `maxTextureSize` is not a usable proxy either — the simulator reports 8192 on hardware that would report 16384. This is the one open item that wants a real device rather than a guess.

## The store

Play requires a privacy policy URL even for an app that collects nothing, and requires it again for the Families programme, which this app qualifies for by construction: no ads, no purchases, no accounts, no chat, no data. Both stores' answer sheets live beside the assets: `mobile/store/PLAY-LISTING.md` and `mobile/store/APP-STORE.md`, with `DECIDE` markers where the call is the owner's rather than the code's. The privacy policy is shared and is **not in this repo** — it is on the company site, one page per app.

Phone screenshots for Play are captured from the real WebView by reconfiguring the emulator to phone geometry (`adb shell wm size 1080x2340 && adb shell wm density 420` → 411×891 CSS px, inside the 480px breakpoint), then padded to an exact 9:16 with black, which is invisible against the game's own sky. Apple's sizes do not transfer: it wants a 6.9" iPhone set and a 13" iPad set at the simulators' native pixel sizes, which is why they are shot separately with `xcrun simctl io <udid> screenshot`. **Both capture tools write RGBA and Apple refuses an alpha channel**, so every file is flattened (`-background black -alpha remove -alpha off -colorspace sRGB -strip`) before upload — and App Store Connect reports that refusal as a *dimensions* error on a file whose dimensions are exactly right, which is a long way to go to find one channel.

Every set is composed by a throwaway script appended to `www/index.html` that walks a list of `{body, camera, overlays}` specs, because neither platform lets the host drive the page. Getting the host and the page to agree on *when* to capture is the whole problem, and three things went wrong before it worked:
- **A fixed schedule cannot be trusted.** `simctl io screenshot` and `adb exec-out screencap` each take a couple of seconds, so cumulative `sleep`s walk a whole window late over six shots; use absolute wall-clock targets. And the page's own clock has to start from something the host can predict — a fixed delay after load, not "when the first bake finished", which differs by seconds between a cold and a warm launch.
- **On Android, prefer a handshake to a clock.** The script marks each finished composition in the app's preferences (`pe-shotdone`), which `adb shell run-as <id> cat shared_prefs/CapacitorStorage.xml` can read immediately, where localStorage is flushed to its file lazily. The script then *holds* the shot on screen for a few seconds so the poll and capture can land, or the next bake starts underneath it and every frame carries a "Scanning surface" banner for the world after it.
- **Contention is the real timer.** An emulator sharing the Mac with three booted iOS simulators took 60s over a bake that takes 2s on its own. Shut the others down before a run.

The iPad set is landscape, and it is the one part of the shoot that is not scriptable: an iPad app that supports Split View must support all four orientations, so a landscape-only `UISupportedInterfaceOrientations` is ignored (the trick that does work on iPhone, where the capture comes out sideways and needs a `-rotate 90`), and `simctl` cannot rotate a device. The simulator has to be turned in its own window by hand; `simctl io screenshot` then still writes the device-native portrait framebuffer with the interface on its side, so each capture needs a `-rotate -90` — the opposite direction from the iPhone case.

Two things will quietly spoil a run, both seen: **another instance of the app still installed and running** — terminating it mid-shoot puts SpringBoard's transition, or the home screen, in the capture window — and **a composition that drifts past its window**, because a bake that overruns pushes every later `setTarget` late (the shot list's `STEP` has to exceed the slowest bake, ~34s on a 2048-map iPad, not the ~7s a single bake measures). `shotlog` is the check: it records the wall-clock ms at which each composition finished, and every capture must land after its own entry.

## Conventions

- Compact style: minimal spacing around operators, single-line helpers, `const $=id=>document.getElementById(id)`.
- Comments explain *why* — real physics, why a value was tuned, what breaks otherwise. Match that register; the physics comments are load-bearing documentation.
- Every clue, debrief, and `fact` string is real science. Keep new copy accurate and written for a young reader.
- Colors and UI chrome come from the CSS custom properties in `:root` (`--amber` for live data, `--chrome` for labels, `--ink` for headings).
